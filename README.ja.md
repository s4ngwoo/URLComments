# 💬 URLComments (どこでもコメントを残せる拡張機能)

🌍 [🇺🇸 English](README.md) | [🇰🇷 한국어](README.ko.md) | [🇯🇵 日本語](README.ja.md) | [🇨🇳 简体中文](README.zh-CN.md) | [🇹🇼 繁體中文](README.zh-TW.md) | [🇪🇸 Español](README.es.md)

**URLComments** は、ウェブ上の正規化されたURLをパブリックなディスカッションスペースに変える、プライバシー重視(Privacy-First)のChrome拡張機能です。記事、ブログ、ドキュメント、ショッピングサイトなど、URLが存在するウェブページならどこでも、短い公開コメントを残してコミュニケーションをとることができます。

---

## 🚀 クイックスタートと使い方 (Usage)

### 1. インストール手順 (拡張機能の読み込み)
1. [GitHub Releases](https://github.com/s4ngwoo/URLComments/releases) から最新の **`URLComments-vX.X.X.zip`** をダウンロードします。
2. ダウンロードした ZIP ファイルを任意のフォルダに解凍します。
3. Google Chrome を開き、アドレスバーに `chrome://extensions` と入力します。
4. 画面右上の **デベロッパーモード** を有効にします。
5. 画面左上の **パッケージ化されていない拡張機能を読み込む** をクリックし、解凍したフォルダを選択します。
6. ブラウザのツールバーで URLComments アイコンを固定（ピン留め）します。

### 2. 使い方
1. **Webページを開く**: コメントを残したい、または読みたい任意のWebページ（ニュース記事、ブログ、ドキュメント、ECサイトなど）にアクセスします。
2. **拡張機能を開く**: ツールバーの URLComments アイコンをクリックしてサイドパネル（またはポップアップ）を開きます。
3. **Googleログイン**: 「Googleでログイン」ボタンをクリックしてサインインします（初回のみ）。
4. **コメントを読む**: そのページの正規化URLに紐づく公開コメントを閲覧します。
5. **コメント・返信・リアクション**:
   - 下部の入力欄に最大1,000文字で意見を入力し、「投稿」ボタンをクリックします。
   - コメントの `↳ 返信` ボタンをクリックしてスレッド返信を行います。
   - 投稿者名の横にある 👍 / 👎 ボタンをクリックしてリアクションを残します。
6. **マイコメントと設定**: 下部ナビゲーションから自分の投稿履歴を確認したり、ダークモード、フォントサイズ、表示言語をカスタマイズできます。

## 🛡️ プライバシー最優先の原則

URLComments は、ユーザーのブラウジング履歴とプライバシーを厳格に保護します：

- **ページ移動時のURL自動送信なし**: ウェブを閲覧したりタブを切り替えたりする際、現在のURLをSupabaseや外部サーバーに自動的に送信することはありません。
- **明示的な操作時のみリクエスト**: ユーザーが拡張機能のポップアップ（またはサイドパネル）を明示的に開き、更新をリクエストしたときにのみ、現在アクティブなタブのURLを読み取り、コメントを取得します。
- **厳格なURL正規化**: クエリパラメータ (`?query=...`) とハッシュフラグメント (`#section`) は完全に除外され、コメントは厳密に `origin + pathname` に基づいてリンクされます。これにより、個人の追跡識別子 (UTM, セッショントークンなど) の流出を根本的に防ぎます。
- **バックグラウンド監視およびテレメトリなし**: バックグラウンドでのポーリング、アナリティクス、テレメトリ、リモートコード実行を一切含みません。

## ✨ 主な機能

- **Google 簡単ログイン**: Supabase Auth と Chrome Identity `launchWebAuthFlow` を介した安全で迅速な認証。
- **正規化URLベースのコメント**: 拡張機能を使用して、正規化されたURLに結びついた最大1000文字の公開コメントを投稿。
- **コンパクトなインライン コメント リアクション (いいね/ひどいね)**: キーボードアクセスを完全に保証しつつ、余白を節約するために、投稿者のニックネームのすぐ横に折り返しなしでコンパクトに配置されたインライン リアクショングループ。
- **コメントの編集と論理削除**: 自分自身のコメントを編集したり、論理削除 (`is_deleted = true`) したりできます。
- **1段階のマルチ兄弟リプライ (1-Depth Multi-Sibling Replies)**:
  - アクティブなトップレベルの親コメントは、複数の兄弟リプライ（返信）を受け取ることができます。
  - リプライは、親コメントの下に作成日時の昇順 (`created_at ASC`) でレンダリングされます。
  - アクティブな親コメントには一貫した `↳ 返信` ボタンが提供され、リプライには追加の返信ボタンは表示されません (1段階の深さ制限)。
- **スレッドベースのインメモリ ページネーション**:
  - トップレベルのコメントスレッドは、ページあたり10個 (`THREADS_PER_PAGE = 10`) 単位で分割レンダリングされ、親コメントと下位リプライが1つのスレッドとしてグループ化されます。
  - ページ切り替え時は、追加のSupabaseネットワークリクエストなしに、インメモリキャッシュから即座にレンダリングされます。
  - 更新時やリプライ作成時にもスクロールとページ位置が保持されます。
- **厳格な時系列昇順ソート (Chronological ASC)**:
  - すべてのトップレベルコメントとリプライは作成日時の昇順 (`created_at ASC`) で一貫してソートされ、同時刻のコメントはbigintセーフな文字列ID比較により安定した並べ替えが行われます。(以前のソートオプション機能は完全に削除されました)
- **独立した多言語 (Language) 設定**:
  - 日本語、英語、韓国語、簡体字中国語、繁体字中国語、スペイン語、およびシステムデフォルトをサポートしています。
  - `chrome.i18n` のブラウザ依存の制限を克服し、カスタムi18nモジュールを通じてユーザーが拡張機能内の言語を即座に上書きできます。
- **独立したフォントサイズ (Font Size) 設定**:
  - 小 (Small)、標準 (Default)、大 (Large) のオプションを提供し、テーマとは独立して `chrome.storage.local` に永続的に保存されます。
  - ルートの `data-font-size` 属性とCSS変数により、ポップアップUI全体が適切にスケーリングされます。
- **投稿者名の安全な省略 (Ellipsis)**:
  - 長いニックネームは視覚的に省略記号(...)で処理され、リアクションボタンなどを押し出すことはありません。同時に `title` と `aria-label` 属性によりフルネームが完全に保持されます。
- **削除された親コメントのコンテキスト保持**:
  - アクティブなリプライが存在するトップレベルコメントが削除された場合、コンテキストを保持するために「削除されたコメントです」というプレースホルダーと既存のリプライを表示し続けます。
  - 削除された親コメントには新しい返信ボタンは表示されず、新たな返信の作成はブロックされます。
- **「自分のコメント」の遅延ロードとキャッシュ無効化**: 下部ナビゲーションの「自分のコメント」タブをクリックしたときのみ履歴をサーバーからロードし、コメントの作成/編集/削除時にキャッシュが自動的に無効化され、常に最新の状態を反映します。
- **テーマ設定の維持**: システムデフォルト / ライトモード / ダークモードをサポートし、設定は `chrome.storage.local` に保存されます。
- **パブリックID ツールチップ**: 投稿者名をホバーまたはキーボードでフォーカスした際に、安全な水平型の固有IDツールチップを提供します。
- **自動高さ調整 Textarea**: 入力内容に応じて、最小48pxから最大140pxの範囲でテキストエリアの高さが自然に調整されます。

## 🔑 拡張機能の権限 (Permissions Audit)

`manifest.json` で定義されているすべての権限は、最小特権の原則に基づいて、実際の使用目的にのみ限定されています：

| 権限 | 使用目的 |
| :--- | :--- |
| `sidePanel` | 拡張機能アイコンをクリックした際、ブラウジングを妨げないChromeのネイティブサイドパネルにUIを開きます。 |
| `storage` | ユーザーのテーマ設定、Supabase認証トークン、タブごとのSPA検知フラグを `chrome.storage.local` に安全に保管します。 |
| `identity` | `chrome.identity.launchWebAuthFlow` を使用して、外部ブラウザウィンドウなしで安全にGoogle OAuthログインを実行します。 |
| `tabs` | 1) `background.js` でタブの有効化/更新イベントを検知し、開いているサイドパネルに手動更新のプロンプトを送信します。 2) 「自分のコメント」から元のURLを新しいタブで開くために `chrome.tabs.create` を呼び出します。 |
| `activeTab` | ユーザーがポップアップを開いた瞬間にのみ、広範な `<all_urls>` 権限なしで、アクティブなタブのURLを一時的に読み取ることを許可します。 |

## 💻 ローカル開発とテスト方法

### 前提条件
- Node.js 18以上
- Google Chrome ブラウザ
- Supabase プロジェクト (PostgreSQL + Auth)

### 1. インストール
```bash
# リポジトリのクローン
git clone https://github.com/s4ngwoo/URLComments.git
cd URLComments

# 依存パッケージのインストール
npm install
```

### 2. Supabase の設定
`lib/config.example.js` をコピーして `lib/config.js` を作成し、Supabaseプロジェクトの情報を入力します：
```javascript
window.APP_CONFIG = {
  SUPABASE_URL: "https://your-project.supabase.co",
  SUPABASE_ANON_KEY: "your-anon-key"
};
```

### 3. ユニットテストの実行
Jestを使用して、すべての純粋な関数、状態フロー、1段階リプライ、およびマークアップの整合性を検証します：
```bash
npm test
```

### 4. Chrome に拡張機能を読み込む
1. Chromeのアドレスバーに `chrome://extensions/` と入力してアクセスします。
2. 右上の **デベロッパー モード** をオンにします。
3. **[パッケージ化されていない拡張機能を読み込む]** をクリックし、`URLComments` ルートフォルダを選択します。

## 🗄️ Supabase マイグレーションの適用

Supabaseダッシュボードの **SQL Editor** で、以下のマイグレーションファイルを番号順に実行します：

1. `001_comments_baseline.sql`: `comments` テーブルの基本スキーマとRLSポリシー。
2. `002_profiles_public_identity.sql`: ユーザープロファイル、表示名、パブリックID生成。
3. `003_comment_votes.sql`: いいね/ひどいね の投票とサーバーサイドカウントトリガー。
4. `004_comment_moderation.sql`: コメントの報告とモデレーションテーブル。
5. `005_verify_schema.sql`: スキーマの整合性検証ビューと関数。
6. `006_fix_linter_warnings.sql`: パフォーマンスとインデックスの最適化。
7. `007_one_depth_replies.sql`: `parent_id` 外部キー、1段階の深さ強制トリガー (`check_comment_one_depth()`)、アクティブリプライ確認関数 (`comment_has_active_replies()`)。

### 📌 リプライポリシーと複数階層ネストについて
- **現在のポリシー**: データベースのトリガーレベルで、リプライに対するリプライ（2段階以上の深さ）を厳格にブロックします。親コメントは複数の1段階リプライを持つことができます。
- **今後の計画**: 2段階以上の深いネスト（入れ子）のリプライは、意図的に除外されています。サポートする場合は、`007_one_depth_replies.sql` トリガーを変更するDBマイグレーションと、再帰的なツリーレンダリングコンポーネントの導入が必要です。

## ⚠️ 既知の制限事項 (Known Limitations)

- **リアルタイム自動更新の非サポート**: プライバシー保護、バッテリー節約、ネットワークコスト削減のため、Supabase Realtime (WebSocket) 購読は意図的に省略されています。最新のコメントを確認するには、手動更新（`↻`）ボタンを押す必要があります。
- **正規化URLベースの照合**: コメントはページの内容ではなく、純粋な正規化URL (`origin + pathname`) に基づいて照合されます。動的に内容が完全に変わるにも関わらず同じURLを共有する一部のウェブアプリでは、コメントスペースが共有されるため注意が必要です。

## 🧪 手動検証チェックリスト

1. **プライバシー検証**:
   - 開発者ツール (F12) の Network タブを開いた状態で、タブを切り替えたりページを移動したりします。
   - 拡張機能がURL情報を含むネットワークリクエストを一切送信しないことを確認します。
   - ポップアップ/サイドパネルを開き、更新を押したときにのみ、正規化URLリクエストが発生することを確認します。
2. **複数の兄弟リプライ検証**:
   - トップレベルのコメント P を投稿します。
   - `↳ 返信` ボタンをクリックして リプライ A を登録します。
   - 再度 P の `↳ 返信` ボタンをクリックして リプライ B を登録します。
   - リプライAとBが親Pの下に作成日時の昇順で表示され、どちらのリプライにも返信ボタンが表示されないことを確認します。
3. **論理削除とコンテキスト保持**:
   - リプライがある親コメントを論理削除します。
   - 親コメントが「削除されたコメントです」に変わり、リプライはそのまま表示されることを確認します。
   - 削除された親コメントの返信ボタンが消え、新しい返信が作成できないことを確認します。
4. **「自分のコメント」検証**:
   - コメントを投稿した後、「自分のコメント」タブに移動し、コメントがリストされていることを確認します。
   - 「元のページを開く」をクリックして、新しいタブで開くことを確認します。
5. **テーマ設定の持続性**:
   - 設定でテーマ（システム、ライト、ダーク）を変更し、拡張機能を閉じて再度開いても設定が維持されることを確認します。
6. **スレッドページネーションと位置保持の検証**:
   - 10個を超えるコメントスレッドがあるページで、ページネーションバー (`< 前へ`, `1 / N`, `次へ >`) が表示されることを確認します。
   - `次へ >` をクリックすると、ネットワークリクエストなしにページ2が即座にレンダリングされ、親コメントとリプライが正しくグループ化されていることを確認します。
7. **フォントサイズとコンパクトヘッダーの検証**:
   - フォントサイズ（小、標準、大）を変更すると、ポップアップUI全体のフォントサイズが即座にスケーリングされることを確認します。
   - いいね/ひどいね ボタンが投稿者名のすぐ右側にインラインでコンパクトに配置され、長いユーザー名が折り返されずに(...)で省略されることを確認します。
