# 🧪 Supabase DBおよびRLS手動検証ガイド

🌍 [English](../SUPABASE_MANUAL_TESTS.md) | [한국어](../ko/SUPABASE_MANUAL_TESTS.md) | [日本語](SUPABASE_MANUAL_TESTS.md) | [中文](../zh/SUPABASE_MANUAL_TESTS.md) | [Español](../es/SUPABASE_MANUAL_TESTS.md)

このドキュメントでは、移行適用後にデータベーストリガーとRLS（Row Level Security）ポリシーが本番環境で意図通り動作するかを確認するための手動テスト手順を説明します。

---

## 1. RLSテストの原則

> [!CAUTION]
> **Supabase SQL EditorではRLSを完全に検証できません。**
> SQL Editorは管理者権限で実行されるため、RLSがバイパスされます。信頼できる検証を行うには、Chrome拡張機能UIから2つの実アカウント（ユーザーA、ユーザーB）を使用してテストする必要があります。

---

## 2. 主なE2Eテスト項目

| 項目 | テストシナリオ | 実行アカウント | 期待される動作 |
|---|---|---|---|
| **1** | **プロファイル作成 & 公開ID** | ユーザーA | 初回ログイン時に表示名と `@...` 形式の公開IDが生成される |
| **2** | **コメント投稿** | ユーザーA | コメント投稿後、DBに `is_deleted = false` で正常保存される |
| **3** | **自分のコメント編集** | ユーザーA | 編集後、UIに `(編集済み)` が表示されDBが更新される |
| **4** | **他人のコメント編集/削除阻止** | ユーザーB | ユーザーAのコメントに対する編集・削除ボタンが表示されず、APIもRLSで遮断 |
| **5** | **1階層リプライ投稿** | ユーザーB | 親コメントに `↳ 返信` からリプライを投稿できる |
| **6** | **ネスト返信の防止** | ユーザーA | リプライ自体には返信ボタンが表示されない（1階層限定） |
| **7** | **通報機能と重複防止** | ユーザーB | 他人のコメントを通報できるが、同一コメントへの重複通報はDB制約で拒絶 |
| **8** | **論理削除とコンテキスト維持** | ユーザーA | 親コメントを削除してもリプライは文脈維持のため表示され続ける |
